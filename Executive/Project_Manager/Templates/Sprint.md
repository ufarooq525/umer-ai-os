# Sprint Template

> A time-boxed commitment of [Tasks](Task.md) drawn from one or more [Epics](Epic.md). The unit the Project Manager reports progress against in the CEO's Daily/Weekly Workflow.

```markdown
# Sprint: <number/name>

## Metadata
- Project: <link to Projects/<name>/>
- Start: YYYY-MM-DD
- End: YYYY-MM-DD
- Status: Planning | Active | Review | Closed

## Sprint Goal
The single sentence this sprint exists to make true — not just a list of tasks. Traceable to the parent Epic's goal.

## Committed Scope
| Task ID | Title | Owner | Estimate | Status |
|---|---|---|---|---|
| | | | | |

## Capacity Check
- Department(s) involved: <list>
- Known capacity constraints this sprint: <list, or "none">

## Dependencies Entering This Sprint
- <dependency and its status — e.g., "Architecture exit artifact — delivered 2026-07-20">

## Risk Register (active this sprint)
| Risk | Likelihood | Impact | Mitigation | Owner |
|---|---|---|---|---|
| | | | | |

## Daily Status Log
| Date | Completed | Blocked | Notes |
|---|---|---|---|
| | | | |

## Sprint Review
- Committed vs. completed: <n of n tasks>
- Acceptance criteria met for all completed tasks: yes/no — if no, itemize
- Carried over to next sprint: <task IDs and reason>

## Retrospective (feeds Core/KNOWLEDGE_STANDARD.md Lessons Learned)
- What went well:
- What didn't:
- Change to make going forward:
```

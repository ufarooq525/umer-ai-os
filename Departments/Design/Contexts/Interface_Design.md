# Bounded Context: Interface Design

Governed by `Departments/Design/DESIGN_CHARTER.md`.

## Purpose

Specify the concrete product interface — layout, content design in-product, visual application of the Design System — ready for Engineering implementation.

## Owns

Interface Design Specs, in-product content presentation specs (not Marketing campaigns).

## Does Not Own

Design System tokens/components authority (Design Systems); production implementation (Engineering); campaign creative (Marketing later).

## Interfaces

Consumes Experience Architecture + Design System; produces specs for Engineering/QA; Constrained by Security for sensitive surfaces.

## Primary Artifacts

Interface Design Spec.

## Anti-Patterns

One-off UI outside Design System without exception; accessibility as afterthought; treating Interface Design as “make it pretty.”

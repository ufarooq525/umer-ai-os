# Engineering Ten-Year Architecture

> Decade spine for Engineering as a Department. Architecture only — no stack, vendor, or model commitments.

Governed by `Departments/Engineering/ENGINEERING_CHARTER.md`, `Departments/DEPARTMENT_ARCHITECTURE_STANDARD.md`.

## Stable Spine (Must Remain True)

1. Engineering owns **technical delivery**, not “coding activity.”  
2. Enterprise Architecture (layer) ≠ Solution Architecture (Engineering context).  
3. QA independence remains sacred.  
4. Security control ownership remains outside Engineering.  
5. Contexts stay concern-based: Solution Architecture, Application Delivery, Platform, Release Engineering, Engineering Systems, Production Observability, Technical Stewardship.  
6. Work enters through Execution; intent traces to Business.  
7. Backend/Frontend/DevOps never become Departments.  

## Evolution Path

| Horizon | Shape |
|---|---|
| Years 0–2 | Single Engineering Department; seven contexts; optional surface Teams; AI-in-production as Application Delivery specialty |
| Years 2–5 | Platform and Release thicken as Teams; split to new Departments only if DAS Split criteria met |
| Years 5–10 | Possible Platform Department or AI Systems Department **only** if Capability ownership and Enabling edges demand it — never by fashion |
| Continuous | Stewardship compounds ADRs, debt register, Intelligence harvest; tools change, contracts do not |

## Explicit Non-Goals for the Decade

- Absorbing Business, QA, Security, or Enterprise Architecture  
- Fragmenting into stack-named Departments  
- Replacing Execution with Engineering-owned workflow engines  
- Treating Technical Debt as a standing Department  

## Split Triggers (DAS)

Split only when: context count persistently >12, Capability ownership conflicts, or Enabling edges dominate the enterprise and create systemic bottleneck that Teams cannot relieve — and both children re-enter Proposed.

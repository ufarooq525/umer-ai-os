# Bounded Context: Technical Stewardship

Governed by `Departments/Engineering/ENGINEERING_CHARTER.md`.

## Purpose

Keep Engineering honest across time — debt portfolio, standards evolution, ADR hygiene. Technical Debt is a practice and artifact stream, not a Department or vanity context name for a team that only complains.

## Owns

Technical Debt Register Entries, Engineering Standards evolution, ADR stewardship hygiene inside Engineering, longevity reviews feeding Ten-Year Architecture.

## Does Not Own

Funding decisions for debt vs features (Business/Executive); Capability registry (EA); org-wide continuous improvement system (Governance) — Stewardship feeds it, does not replace it.

## Interfaces

Consumes Delivery/Platform reality; produces debt proposals into prioritization; harvests lessons toward Intelligence; aligns standards with Core/Standards.

## Primary Artifacts

Technical Debt Register Entry, Engineering Standard, ADR (joint with Solution Architecture).

## Anti-Patterns

Debt denial; debt-only mode; standards that contradict Core; “Stewardship” as blocker theater without evidence.

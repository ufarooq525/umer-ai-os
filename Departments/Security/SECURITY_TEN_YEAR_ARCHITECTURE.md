# Security Ten-Year Architecture

Governed by `Departments/Security/SECURITY_CHARTER.md`.

## Stable Spine

1. Security remains Enabling with Constraining authority — not a mandatory build stage for all work.  
2. Governance owns risk policy; Security owns controls and assurance.  
3. Engineering implements; Security does not become a delivery factory for product features.  
4. Contexts: Security Architecture & Threat Modeling, Identity & Access Control, Product & Application Security, Compliance & Control Assurance, Vulnerability & Security Response.  

## Evolution

Identity implementation Services may thicken in Engineering; control accountability stays Security. Future Legal/IT Departments attach as Constraining/Enabling peers — do not merge into Security by default.

## Non-Goals

Replacing Governance; replacing QA; corporate HR security theater as primary mandate.

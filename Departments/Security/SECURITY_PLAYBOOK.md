# Security Playbook

Governed by `Departments/DEPARTMENT_ARCHITECTURE_STANDARD.md` §12.

## 1. Mandate

Security defines and assures controls so delivery can be safe and risk can be honest.

## 2. Placement

Domain Security · Enabling topology · Constraining peers: Eng, Design, QA, Analytics.

## 3. Enter / Leave

Enter via Execution-designated security relevance or vuln/incident intakes. Leave as requirements, procedures, assurance evidence, and exception recommendations.

## 4. Contexts

Threat Modeling shapes Architecture → Identity and AppSec specify → Compliance assures → Response handles vulns/incidents.

## 5. Example

Auth Capability initiative → Threat Model + Identity Spec → Eng implements → QA runs Security Verification Procedure → Assurance Evidence to Governance → residual risk logged if exceptions.

## 6. Business Traceability

Security constrains value pursuit; it does not invent product scope. Commercial risk acceptance stays Executive/Human Principal.

## 7. Inheritance

Core Security gate + Governance Risk Framework by link.

## 8. Escalation

Deadlock with Eng → CEO; Critical vuln → Risk Critical path; process failure → CoS.

## 9. Anti-Patterns

Pipeline capture; Governance capture; checkbox models; silent exceptions.

## 10. Summary

**Security owns controls and assurance — Architecture, Identity, AppSec, Compliance, Response — while Governance scores risk and Engineering implements.**
